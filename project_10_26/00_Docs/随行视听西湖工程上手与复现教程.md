## 2 用最少术语理解整个系统

FPGA 是一块可以按代码搭建数字电路的芯片。Verilog 描述的是同时工作的电路，和电脑上从第一行往下运行的 Python 有很大不同。下面的链条先记住即可。

TF 卡里的 BMP → SPI 读字节 → BMP 解析出像素 → SDRAM 保存一整张图 → 按视频时序取像素 → 叠加字幕 → HDMI 发射器 → 显示器。

按键 → 消抖 → 播放控制器 → 指定下一张图；播放控制器还负责等写入结束，通知视频部分在帧边界换图。声音由另一条同步电路生成 PCM 数值，连同图像交给 HDMI 发射器。

### 2.1 七个你会反复遇到的词

|术语|通俗解释|本项目中的例子|
|---|---|---|
|像素|图像上的一个小色点|640×480 共 307200 个|
|RGB|红绿蓝三个颜色分量|每分量 8 位，总共 24 位|
|时钟|电路统一迈步的节拍|像素时钟 25 MHz|
|状态机|按条件在几个步骤间移动的流程控制器|等待卡、读目录、读图片、报错|
|FIFO|先进先出的缓冲队列|把读卡节奏与存储节奏分开|
|帧缓存|存放一整张画面的内存区域|两块各 307200 个 32 位字|
|ROM 字模|预先准备的文字点阵|白色字在哪个像素亮，由一位决定|

### 2.2 为什么要有两块缓存

把显示中的图片想成桌面上的一张纸。若边看边把新图直接涂在纸上，会看到上半张是旧图、下半张是新图。双缓冲准备两张纸：显示前台那张，后台写另一张。后台完整写好后，在一帧结束的空白时间换纸。

本工程进一步区分三个事件：读卡送完像素、SDRAM 真正收完像素、视频部分真正接纳新缓存。三者都确认后才允许重用旧缓存。不能把“读卡读完了”当成“新图已经安全显示了”。

### 2.3 几个关键数字

一张 BMP 的文件大小为 54 + 640×480×3 = 921654 字节。FPGA 内部每个像素用 32 位存储，最低 8 位补零，因此一帧占 1228800 字节，两帧占 2457600 字节。缓存地址 0 和 307200 是 32 位字地址，不是字节地址。

视频总时序是每行 800 个时钟、每帧 525 行，包含可见画面之外的消隐时间。25 MHz / 800 / 525 约等于 59.52 帧每秒；本文不把它写成精确 60.000 Hz。显示器是否接受这一时序必须上板验证。

### 4.1 顺着第一张图走一遍

1. 上电后等待两组 PLL 锁定，再等约 20 ms，各时钟域依次退出复位。
2. 原厂 SPI 控制器初始化 TF 卡。媒体读取器等待 sd_ready。
3. 读取固定目录扇区 LBA 2056，取得四张图片的起始扇区和长度。
4. 依次检查四张 BMP 的文件头。即使第 4 张不合法，也不会把目录判为正常。
5. 播放控制器发出 load_start，指定第 0 张和缓存 0。
6. 图片读取器向 SDRAM 写入模块发请求，收到确认并完成释放握手后，开始送像素。
7. BMP 像素按 B、G、R 字节出现，读取器重排为 R、G、B；写缓存时把行顺序倒过来，纠正 BMP 自下向上的存储方式。
8. 读卡完成与 SDRAM 写完都发生后，控制器翻转 publish_toggle。
9. 视频侧等到下一次帧请求，接收缓存编号，留出地址稳定时间，再向读缓存模块请求。
10. 内存读请求获得确认后，允许显示图像，返回发布确认，并产生一次 arrival_event。

第 10 步以前图片区域被遮成黑色；字幕和 HDMI 测试音仍可能先出现。这不是卡数据已经读入的证据。

### 4.2 读图状态和错误码

|数码管状态|含义|首先检查|
|---|---|---|
|0|等待 SD 初始化|卡是否插好、卡类型、电源和 SPI 引脚|
|1|读取媒体目录|是否写入本项目完整镜像|
|2|检查四张 BMP 头|目录指向的文件是否匹配|
|3|正在装入一张图|稍等；持续过久则看超时码|
|4|读取器就绪|正常状态；最后写入和显示提交可能还在收尾|
|b|整帧装入或显示确认超过约 20 秒|SDRAM 完成通知、帧请求及确认链路|
|C|一次读取或写请求握手无进展约 2 秒|TF 卡或 SDRAM 写入确认|
|d|BMP 头不符合要求|必须使用生成脚本制作的四张 BMP|
|E|目录不合法|完整重写卡镜像，不要只复制 BMP|
|F|异常状态|复位，保留日志和复现步骤|

WAIT_SD 不设置超时，未插卡可能一直显示 0。软件不会自动修复卡，也没有实现所有 SD 底层错误的专用错误码。数码管只能提供定位线索。

### 4.3 控制器里最重要的几个寄存器

load_id 是下一张待装入图片的编号。displayed_id 表示已完成显示提交的站点。write_buffer 表示当前后台写入哪一块内存。publish_buffer 和 publish_id 在跨时钟交接过程中保持稳定，直到收到确认。

source_seen 记录读卡是否完成，write_seen 记录 SDRAM 是否写完。pending_next 只保留一个排队的下一站请求；读图中连续按三次不会承诺连续跳三站。这样可以避免按钮抖动和重复点击导致长队列。

### 4.4 字幕为什么不直接画进照片

TF_BMP 中的图片不带字幕。wl_osd 每个像素都判断是否在文字区域，如果字模对应位为 1，就输出文字颜色，否则输出照片颜色；上方和下方的底图亮度缩小为四分之一，以便看清文字。

中文使用 captions.hex，包含四套 640×96 的点阵；上面 32 行放标题，下面 64 行放站点和介绍。数字及英文字母使用 ascii_font.hex。模式、周期、站号、运行时间由寄存器实时选择字符，因此不是一张静态合成图。

ROM 是同步读取的，取到文字需要经过流水线。因此 hs、vs、de 和 RGB 必须一起延迟，不能只延迟字幕。OSD 的测试台逐像素比较实际输出与独立软件参考图，能发现偏一拍、错一行等问题。

### 4.5 声音的实现

本工程使用像素时钟域内的 PCM 发生器。相位累加器产生约 440 Hz 三角波测试音，输出左右声道相同的数据。48 kHz 指每秒 48000 个采样点，不是听起来有 48000 Hz 那么高的音调。

25 MHz 不是 48 kHz 的整数倍，所以采样间隔交替为 520 或 521 个时钟。累加方法保证名义 25000000 个时钟产生 48000 次有效采样。真实频率还随板载晶振误差变化。

HDMI 发射器接收 PCM 和 ACR 参数：N=6144，CTS=25000。根据 Fs = F_TMDS×N÷(128×CTS)，名义采样率为 48 kHz。每 48 个采样产生一次 ACR 更新。该方案使用 IP 的 PCM 输入接口，不走原例程的音频 PLL 和 I2S 环回路径。

提示模式持续约 0.4 秒，先约 660 Hz 后约 880 Hz；每次新站点真正提交时触发。上电默认测试音模式，便于首先验证声音链路。提示音模式无到站事件时持续送零值采样，而不是关闭 HDMI 音频时钟。

屏幕 STOP 表示手动停留，AUTO 表示自动模式；TEST 是持续测试音，CHIM 是提示音模式。P 是当前停留秒数；U 是从复位后开始累计的分钟和秒，99:59 后回到 00:00；S=2/4 表示当前第 2 站。下方黄色标记跟随站点变化。

## 6 图片和 TF 卡镜像怎么制作

### 6.1 已经准备好的素材

01_Assets\Original 内是四张原始 JPG。01_Assets\TF_BMP 内是四张标准 BMP。prepare_assets.py 按照片原始比例缩放并补边，不强行拉伸；文件宽度 640 正好使每行 1920 字节对齐，不需要额外行填充。

图片按正常 BMP 格式存放，正高度表示文件从最底行开始记录。读取器要求 54 字节头、24 位颜色、无压缩、正高度 480 和宽度 640。32 位 BMP、带额外色彩头的 BMP、PNG 改扩展名等都会被拒绝。

替换照片时覆盖对应 Original JPG，保持四个文件名与顺序，再执行 03_Rebuild_Assets.cmd。中文字体使用本机微软雅黑，ASCII 使用 Consolas；队友电脑缺少这些字体时先补齐或在脚本内指定等价字体。

### 6.2 为什么必须写入整张镜像

WestLake_TF_128MiB.img 是一个普通文件，大小 128 MiB；生成它没有访问任何物理磁盘。文件中已有分区表、FAT32 引导区、两份 FAT、根目录和四张连续存储的 BMP。

FPGA 并不实现通用 FAT32 文件系统，也不按文件名查文件。它读取固定 LBA 2056 的专用目录，再按目录指定的扇区读取连续数据。所以，把四张 BMP 拖进一张随意格式化的卡不会满足这个工程的条件。写入后不要在卡上删除、替换或拖动图片；换图应重新生成并重写镜像。

目录中保存了 ID、文件长度和 CRC32。电脑端校验脚本检查这些字段以及完整文件内容；当前 FPGA 检查目录魔数、分辨率、长度、地址边界及四个 BMP 头，没有对每张图执行 CRC32 全文校验。不要在报告中写成具备完整硬件 CRC 保护。

### 6.3 下午写 TF 卡的操作

1. 使用专用于比赛且已备份的 TF 卡，建议先用队友已经成功运行例程的 SDHC 卡。把卡接入读卡器。
2. 选择支持原始磁盘镜像的工具，例如 Win32 Disk Imager；从工具官网获取。不要运行原参考资料里的 sync_to_sd.py。
3. 选 01_Assets\WestLake_TF_128MiB.img。通过容量、盘符和拔插变化核实目标就是这张 TF 卡。
4. 写入会覆盖目标卡的分区与数据，确认备份及目标后再执行 Write。不要选择电脑系统盘或其他 U 盘。
5. 完成后使用工具的 Verify 检查写入结果，并安全弹出。Windows 可能只看到约 127 MiB 分区，这符合当前小容量演示镜像，不代表大卡损坏。
6. 在开发板断电时插卡，再接通电源。后续更换镜像重复相同步骤。

如果 Windows 提示初始化或格式化，不要按提示重新格式化已写好的卡。先检查工具是否按整盘写入、卡是否正确弹出和插入。本教程没有提供自动选择物理磁盘的写卡脚本，避免一次点击选错设备。

## 7 仿真结果到底证明了什么

仿真是让电脑按时钟推进 Verilog 电路，测试台主动输入数据并检查输出。它可以精确发现逻辑错误，但不能替代电压、电缆、TF 卡品质和显示器兼容性测试。

|测试台|验证内容|通过证据|
|---|---|---|
|tb_media.sv|真实卡镜像的四图读取；坏目录、坏第 4 图头和超时|四图 1228800 个 RGB 像素完全一致|
|tb_audio.sv|采样节奏、双声道、ACR、提示长度和静音|25000000 拍产生 48000 样本及 1000 次 ACR|
|tb_osd.sv|四站标题、字幕、状态和线路位置|1228800 个输出像素与独立渲染结果相同|
|tb_control.sv|完成顺序、切帧确认、缓存保护、排队、自动与超时|自检 PASS，并生成 control.vcd|
|tb_framebuffer.sv|两个缓存全帧地址、BMP 翻转和读写仲裁|614400 写地址与 614400 读地址检查通过|
|tb_key.sv|短抖动、长按、松开再按|长按仅一事件，第二次按下正常|
|tb_status.sv|时间数码进位与回卷|00:59→01:00，99:59→00:00|

媒体测试使用的是扇区接口模型，没有模拟 TF 卡完整 SPI 电气协议。缓存测试检查地址控制和仲裁，使用理想 FIFO 占用量；它不是包含 SDRAM 芯片模型的整机吞吐验证。原厂加密 HDMI 与 SDRAM IP 没有在 Icarus 中进行完整物理链路仿真。

### 7.1 学会读一次失败

打开某个 .log，先找 FATAL 或 error。比如 pixel 123 actual … expected … 代表第 123 个像素与期望值不同，应先检查 BGR/RGB 顺序和头部偏移。global timeout 代表握手或状态机没有在测试规定时间内结束，先看请求和确认是否互相等待。

修改代码后，先运行相关测试，再运行全套。不要修改测试的预期值来掩盖错误。仿真返回非零退出码时，不把旧日志或旧 .bit 当作新版本通过的证据。

### 7.2 波形怎么读

04_Sim\control.vcd 可用支持 VCD 的查看器打开；若当前安装目录包含 GTKWave，可在其文件菜单打开该文件。先加入 load、source_done、wr_toggle、pub、treq、mreq、mack、pack、rbuf 和 state。

观察顺序应是 load 发起；source_done 与 wr_toggle 都出现；pub 翻转；到 treq 后 rbuf 更新；延迟几拍 mreq 拉高；mack 到达后 pack 返回；最后下一次 load 才能重用旧缓存。你能在波形中把这一段指出来，就已经理解核心安全切图流程。

## 8 编译与时序报告怎么读

### 8.1 从源码到板上电路

综合把 Verilog 转成查找表、寄存器和存储块。布局决定这些资源放在芯片哪里，布线决定如何连接。时序分析检查信号能否赶在下一次采样前稳定。bitgen 将最终配置生成 .bit 文件。

tools\run_td.py 生成的 build_westlake_generated.tcl 保留了本次实际执行命令。它使用单次运行流程，依次加载工程、引脚约束、时钟约束和 FIFO IP 约束，然后实现并报告。不要运行 tools\_history 中的历史调试脚本。

### 8.2 本次最终结果

|指标|数值|如何理解|
|---|---|---|
|建立时间最差余量 SWNS|0.157 ns|受约束路径没有负建立余量|
|保持时间最差余量 HWNS|0.011 ns|受约束路径没有负保持余量|
|建立与保持总负余量|均为 0|报告中的相关违例已清除|
|STA 覆盖率|99.64%|不是所有外部引脚接口都完整建模|
|LUT|4928 / 19600|约 25.14%|
|寄存器|3854 / 19600|约 19.66%|
|9 Kb BRAM|51 / 64|约 79.69%，字幕点阵占较多存储|
|PLL|2 / 4|系统一组，视频一组|

原始基线同样做了独立编译，其 SWNS 为 -6.699 ns。正式工程将 SDRAM 从 125 MHz 调整为 50 MHz，并把输出相位调整为 144°，使写方向有约 8 ns、读方向有约 12 ns 的时钟间隔。同步更新了刷新周期参数。视频像素仍为 25 MHz，串行时钟仍为 125 MHz。

没有沿用原例程把视频与 HDMI 串行时钟设为互斥的约束；它们同时工作且有关联，应该被分析。当前也没有用整组异步假路径来掩盖存储时序问题。

### 8.3 仍需保留的限制

日志仍有供应商 IP 相关告警，包括 SDRAM 初始放置位置调整、SDRAM 时钟使用局部布线、部分未连接引脚和端口位宽提示。ROM 在 TD 中也会出现无常规写入驱动的提示，但初始化清单已经确认 31 个 overlay BRAM 块均带初始化数据，且没有缺失字模文件的告警。

时序余量较小，外部 SPI、DDC 等接口没有完整的板级输入输出延时模型。因此正确表述是“当前受约束路径通过静态时序检查，待硬件验证”，不能写“全板所有工况已验证稳定”。SDRAM 降频后的视频连续供数、TF 卡读写节奏和 HDMI 兼容性尤其要在板上观察。

不要为了让报告变绿随意添加 set_false_path。如果要调整 PLL，相应 .v、.ipc、global_def.v 和时序报告都要一起检查。IP 配置文件已同步更新；随意点击重新生成 PLL 还可能丢失本项目额外导出的锁定信号端口，修改后需要复查顶层连接。

## 9 换电脑如何复现

## 10 下午拿到板子以后一步一步做

### 10.1 先核对设备

确认实物是 HX4S20C，核对板载 FPGA 丝印、跳线、供电、JTAG 下载口、TF 卡插槽、HDMI 口及按键编号。接一台明确支持 HDMI 音频的电视或显示器。只有视频输入而没有扬声器的显示器无法验证声音要求。

队友已经跑过例程，先让队友复现那份已知可用例程，确认板卡、下载器、线缆和显示器组成的链路仍正常。记录例程名称和使用的 TF 卡。随后切换到本项目，便于分清硬件问题与工程问题。

### 10.2 先做临时下载

1. 断电插入写好的专用 TF 卡，连接 HDMI 和下载器，再按板卡手册供电。
2. 打开 TD 配套下载工具，扫描 JTAG 链，确认识别到正确器件。扫描不到时先排驱动、供电和连接。
3. 为 FPGA 配置操作选择 05_Build\westlake\westlake.bit，先执行 SRAM 临时配置。具体按钮名称以当前下载工具为准。
4. 等数码管经历读卡状态并进入 4，屏幕出现第 1 站。应能听到连续测试音；先降低电视音量再逐步调整。
5. 按 KEY2，依次检查 2、3、4、1 四站，注意上下方向、颜色、文字与图片是否匹配。
6. 按 KEY4 开启自动；确认 AUTO 字样。改开关后手动切一次使周期生效，再开启自动观察。
7. 按 KEY3 切到 CHIM；静止时应安静，切图提交后应有短提示音。
8. 连续运行至少 10 分钟，做快速按键、长按、切换模式、复位等操作，记录是否出现破图、音频中断或锁死。

首次出问题只改变一个条件，例如只换 HDMI 线或只换 TF 卡。不要同时改 PLL、引脚和状态机，否则很难判断是什么修好了问题。

### 10.3 再做 Flash 固化和冷启动

SRAM 下载成功后，断电配置会消失。基础任务要求上电自动运行，所以还必须把设计写入板载配置 Flash。

1. 核对实物 Flash 芯片型号及容量，必要时用下载工具读取 JEDEC ID；旧资料中容量描述存在差异，不能凭一个旧截图选择器件。
2. 按板卡手册及 TD 下载工具的 Flash 流程，选择与实际芯片一致的器件项和配置模式。
3. 使用工具支持的位流格式执行擦除、编程、校验；若工具要求专用 Flash 文件，用 TD 正式转换或生成。不要把 .bit 直接改后缀成 .bin。
4. 完成后关闭电源，断开不必要的下载连接，保留正确的启动模式和 TF 卡，再重新上电。
5. 不点击电脑下载按钮，验证画面、测试音、按键和自动播放均恢复。至少做三次断电启动，并录一段能看到上电过程的视频。

只有这一步实测通过，才能把“已固化，上电即运行”填写为完成。当前交付中的验收表将它保留为待验证。

## 11 常见问题按现象排查

|现象|先检查|再定位|
|---|---|---|
|编译时找不到模块|是否打开正式 .al，源目录是否完整|查看日志第一个 ERROR，确认 IP 目录|

|出现 C 或 b|卡是否卡住、SDRAM 是否完成|分别查看读请求、写确认、帧确认|
|图像上下倒置|写缓存 WRITE_V_FLIP|是否误换成负高度 BMP|

|临时下载好但断电失败|是否真正执行 Flash 编程与校验|Flash 型号、启动配置和供电时序|

求助时提供：正在用的工程路径、是否重新编译、数码管代码、屏幕现象、第一条 ERROR、刚才改过的文件。不要只发“不能用了”。把新实测记录保存到 00_Docs，后续在同一个任务中继续，我就能沿着当前工程排查。

随行视听西湖导览终端基于 HX4S20C FPGA 开发板，以少年宫断桥、涌金门、雷峰塔和岳庙四个站点为演示场景。系统从 TF 卡读取标准 BMP 图片，通过 SDRAM 双缓冲组织视频输出，并在 HDMI 画面上实时叠加站点介绍、下一站、运行时间和播放模式。用户可通过按键手动切站或自动轮播，并选择持续测试音或到站提示音。电脑端已完成模块仿真、工程实现与时序检查，实机测试结果待补充。
