# 淡入淡出提前露出新图：修复记录

## 用户现象

图片有时先切到新图，随后才播放淡出/淡入动画。

## 根因与最小修改

`SD/frame_fifo_read.v` 在淡出前半段需要读取旧图。原逻辑对两位缓冲区索引取反：

```
effective_idx = fade_old ? (~read_addr_index_d1) : read_addr_index_d1;
eff_base = effective_idx == 0 ? read_addr_0 : read_addr_1;
```

新图编号为0时，取反得3，后续选择1，恰好是正确旧图。
新图编号为1时，取反得2，后续仍选择1，读的却是新图。
因此某个物理缓冲区方向会把新图提前显示，再对它执行淡出。

修复直接选择已定义的新/旧基地址：`eff_base=fade_old?old_base:new_base`，
配对地址相反；不改变动画时长、系数、音频、SD素材或频谱。

## 回归证据

新增 `tb_transition_pipeline.sv`，集成帧提交、转场控制及真实SDRAM读地址生成，
模拟25MHz视频/50MHz内存时钟，以及VS下降沿请求、上升沿推进的真实相位关系。

- 原源码快照：首个淡出像素实际读取307200（新图），期望0（旧图），测试失败。
- 修复后：308帧通过，覆盖两个方向淡入淡出、四种转场轮换、站点直接切换和提交握手。
- `framebuffer` 回归补接固定禁用转场输入，使用能识别X态的地址比较，避免悬空输入漏报。
- 原有 `transition`、`fade_lookup`、`scene`、`control` 回归通过。
